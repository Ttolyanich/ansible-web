Современная веб-панель для централизованного управления распределенной серверной инфраструктурой (500+ серверов). Автоматически синхронизирует инвентарь из **Zabbix API**, обеспечивает высокопараллельную диагностику доступности по SSH, предоставляет каталог плейбуков с YAML-редактором, справочник сотрудников для массового онбординга/оффбординга и потоковый вывод логов в реальном времени.

---

## ⚡ Ключевые возможности

### 1. 🔄 Динамическая синхронизация с Zabbix API
- **Импорт структуры:** Автоматический сбор групп хостов (компаний, филиалов) и активных серверов через Zabbix JSON-RPC API.
- **Интеллектуальное определение ОС:** Автодетект типа ОС по назначенным шаблонам и именам (`Linux`, `Windows Server`, `Сетевое оборудование / Роутеры`).
- **Умное извлечение IP и портов:** Если сервер находится за NAT/VPN, панель автоматически парсит VPN-адрес и нестандартный SSH-порт из описания/комментария хоста в Zabbix (`VPN: 10.x.x.x`, `порт: 2222`).
- **Защита ручных настроек:** Возможность зафиксировать кастомный IP, порт или тип ОС вручную без перезаписи при последующих синхронизациях.

### 2. 👥 Справочник сотрудников (Staff Directory)
- **Каталог персонала:** Ведение списка системных администраторов, инженеров и сервисных аккаунтов с привязкой публичных SSH-ключей.
- **1-Click массовый онбординг:** Выберите сотрудника (или нескольких) и разверните их учетные записи с sudo-правами на сотни целевых серверов в один клик.
- **1-Click отзыв доступа (Оффбординг):** Мгновенное удаление учетной записи, завершение активных процессов (`pkill`) и удаление правил `sudoers` при увольнении или ротации.
- **3-уровневая защита служебных учеток:** Системные сервисные аккаунты (например, `ansible`, `root`, `admin`) защищены от случайного удаления в коде веб-приложения, API и на уровне плейбука.

### 3. 📖 Менеджер плейбуков (Playbooks Manager)
- **Каталог и запуск:** Запуск задач автоматизации на любых произвольных комбинациях хостов и групп.
- **Встроенный YAML-редактор:** Редактирование плейбуков прямо в браузере с подсветкой синтаксиса и валидацией перед сохранением.
- **Готовые производственные шаблоны:**
  - `system_update.yml` — обновление системных пакетов (APT, YUM, DNF, Pacman).
  - `service_restart.yml` — управляемый перезапуск системных демонов (systemd).
  - `disk_space_audit.yml` — аудит дискового пространства и предупреждения о переполнении (`df -h`).
  - `docker_cleanup.yml` — очистка неиспользуемых Docker-контейнеров, образов и томов.
  - `user_create.yml` / `user_delete.yml` — управление пользователями на Linux и Windows.

### 4. ⚡ Высокопараллельный SSH Ping Check
- **Сверхбыстрый опрос:** Проверка сотен серверов за 30–60 секунд (`forks: 100`, `ConnectTimeout: 10s`, `gather_facts: false`).
- **Единый транспорт:** Унифицированный опрос как Linux-серверов, так и Windows Server (через встроенный OpenSSH).
- **Живая статистика:** Наглядные бейджи статусов (`online`, `unreachable`, `auth_error`, `unknown`) и время последнего успешного отклика.

### 5. 📡 Потоковый Live-лог и управление задачами
- **Real-time вывод (SSE):** Просмотр логов выполнения Ansible в реальном времени построчно без задержек и перезагрузки страницы.
- **Мгновенная отмена:** Возможность в любой момент остановить зависшую или ошибочную задачу кнопкой «Остановить задачу» (грамотное завершение процессов Ansible).
- **Повтор сбойных хостов в 1 клик:** Кнопка **«Повторить для сбойных хостов»** позволяет моментально перезапустить задачу исключительно по серверам со статусом `failed` или `unreachable`.
- **Авто-подбор учетных данных (Credential Cycling):** Если основной профиль не подошел, движок автоматически пробует альтернативные профили авторизации (ключ &rarr; пароль &rarr; запасные профили).

### 6. 🛡️ Безопасность и отказоустойчивость
- **Шифрование данных:** Все пароли, токены и приватные SSH-ключи хранятся в БД в зашифрованном виде с использованием алгоритма **Fernet (AES-128-CBC)**.
- **Поддержка Legacy-ключей:** Встроенная поддержка старых приватных ключей (OpenSSL 3.0 Legacy Provider для DES-EDE3-CBC).
- **Безотказный POSIX Shell Fallback:** Плейбук создания пользователей автоматически откатывается на чистый POSIX Shell (`raw`), если на удаленном сервере поврежден или отсутствует Python (роутеры, шлюзы, минималистичные дистрибутивы).
- **Аудит действий:** Полный журнал событий (Audit Log) фиксирует, кто, когда и какие действия выполнял в системе.

## 📂 Архитектура проекта

```text
ansible-web/
├── app.py                      # Flask веб-сервер, роутинг, API и контекстные процессоры
├── models.py                   # Схема SQLAlchemy (SQLite) с шифрованием Fernet AES
├── zabbix_client.py            # Интеграция с Zabbix API (JSON-RPC 2.0), парсинг IP/портов
├── task_engine.py              # Асинхронный движок запуска Ansible, генератор инвентаря
├── ansible.cfg                 # Оптимизированный конфиг Ansible (pipelining, forks, remote_tmp)
├── openssl_legacy.cnf          # Конфиг OpenSSL для расшифровки ключей legacy-формата
├── playbooks/                  # Каталог YAML плейбуков
│   ├── ping_check.yml          # Плейбук быстрой проверки доступности
│   ├── user_create.yml         # Создание пользователей с fallbacks (Linux + Windows)
│   ├── user_delete.yml         # Удаление пользователей и очистка sudoers
│   ├── system_update.yml       # Массовое обновление пакетов
│   ├── service_restart.yml     # Перезапуск сервисов
│   ├── disk_space_audit.yml    # Мониторинг заполнения дисков
│   └── docker_cleanup.yml      # Очистка Docker
├── templates/                  # Jinja2 шаблоны с темной темой (Tailwind CSS)
├── static/                     # Статические ресурсы и стили
├── Dockerfile                  # Мультиплатформенный образ (Python + Ansible-core + OpenSSH)
├── docker-compose.yml          # Развертывание в Docker
├── requirements.txt            # Зависимости Python
├── test_system.py              # Автоматизированный тестовый набор
└── .env.example                # Шаблон переменных окружения
```

## 🚀 Быстрый запуск

### Вариант 1: Запуск через готовый Docker-образ (Рекомендуется)

Проект настроен на автоматическую сборку образов через **GitHub Actions** в **GitHub Container Registry (GHCR)**.

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/Ttolyanich/ansible-web.git
   cd ansible-web
   ```

2. Создайте файл окружения `.env`:
   ```bash
   cp .env.example .env
   ```
   *Сгенерируйте и укажите свой уникальный `FERNET_KEY` и `SECRET_KEY`:*
   ```bash
   python -c "from cryptography.fernet import Fernet; print('FERNET_KEY=' + Fernet.generate_key().decode())" >> .env
   ```

3. Запустите контейнер:
   ```bash
   docker compose pull ansible-web
   docker compose up -d ansible-web
   ```

4. Откройте панель в браузере: `http://<IP_вашего_сервера>:5050`

---

### Вариант 2: Локальный запуск (Python)

1. Создайте виртуальное окружение и установите зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # на Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Настройте `.env` файл:
   ```bash
   cp .env.example .env
   ```

3. Запустите тесты:
   ```bash
   python test_system.py
   ```

4. Запустите сервер:
   ```bash
   python app.py
   ```

## 🛠️ Первоначальная настройка

1. **Подключение Zabbix:**
   - Перейдите в **«Настройки»** (`/settings`), укажите URL вашего Zabbix сервера (например, `https://zabbix.yourdomain.com/api_jsonrpc.php`) и API токен.
   - Нажмите «Проверить подключение» и сохраните настройки.
2. **Синхронизация инвентаря:**
   - Нажмите **«Синхронизировать Zabbix»** на дашборде. Все группы и серверы будут импортированы с автоопределением ОС и VPN-маршрутов.
3. **Настройка профилей подключения:**
   - В разделе **«Ключи SSH»** (`/credentials`) настройте профили по умолчанию для Linux (`root` или пользователь с правами sudo) и Windows (`Administrator`).
   - При необходимости переопределите профили для отдельных хостов или групп.
4. **Проверка доступности:**
   - Нажмите **«SSH Ping всех хостов»** для моментального получения актуального статуса всей инфраструктуры.
